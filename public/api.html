SIMPLEBANK · SYSTEM DESIGN PRACTICAL

REST API reference

A quick guide to the demo endpoints, request shapes, and response codes.

BASE URLhttp://localhost:3000
LOW-LEVEL DESIGNOne request, through the system
Customer→Frontend→Express REST API→Banking Service→Data Storage→JSON Response

The browser sends JSON to a route. The route calls the banking service, which reads or changes the in-memory data and returns a result.

ACCOUNTS

Read account information

GET/accounts/:idGet account details

Example request

GET /accounts/1024

Example response · 200 OK

{
  "account": {
    "id": "1024",
    "customerName": "Alex Morgan",
    "accountNumber": "•••• •••• 1024",
    "accountType": "Savings Account",
    "status": "Active",
    "balance": 48250.75,
    "currency": "INR"
  }
}

404 Account ID does not exist.

GET/accounts/:id/balanceCheck the current balance

Example request

GET /accounts/1024/balance

Example response · 200 OK

{ "accountId": "1024", "balance": 48250.75, "currency": "INR" }

404 Account ID does not exist.

GET/accounts/:id/transactionsList account transactions

Example request

GET /accounts/1024/transactions

Example response · 200 OK

{
  "accountId": "1024",
  "transactions": [
    {
      "id": "TXN-24018",
      "beneficiary": "Jordan Lee",
      "amount": -1250,
      "date": "2026-10-07T10:25:00.000Z",
      "status": "Completed"
    }
  ]
}

404 Account ID does not exist.

TRANSFERS

Send a demo transfer

POST/transfersValidate and record a transfer

Example request · JSON

POST /transfers
Idempotency-Key: demo-transfer-001
Content-Type: application/json

{
  "fromAccount": "1024",
  "beneficiaryId": "B001",
  "amount": 500,
  "remarks": "Monthly payment"
}

Example response · 201 Created

{
  "transaction": {
    "id": "TXN-58321",
    "beneficiaryId": "B001",
    "beneficiary": "Jordan Lee",
    "amount": -500,
    "date": "2026-10-09T10:00:00.000Z",
    "status": "Completed",
    "remarks": "Monthly payment"
  },
  "availableBalance": 47750.75,
  "replayed": false
}

400 Invalid amount, missing idempotency key, or insufficient balance. 404 Account or beneficiary not found. 409 Key reused for a different request. Repeating the same key and request returns the original result with 200 OK.

BENEFICIARIES

Manage saved recipients

GET/beneficiariesList demo beneficiaries

Example request

GET /beneficiaries

Example response · 200 OK

{
  "beneficiaries": [
    { "id": "B001", "name": "Jordan Lee", "bankName": "Northstar Bank", "accountNumber": "•••• 8842" }
  ]
}
POST/beneficiariesAdd a demo beneficiary

Example request · JSON

POST /beneficiaries
Content-Type: application/json

{ "name": "Jamie Patel", "bankName": "Northstar Bank", "accountNumber": "12345678" }

Example response · 201 Created

{
  "beneficiary": {
    "id": "B12345678",
    "name": "Jamie Patel",
    "bankName": "Northstar Bank",
    "accountNumber": "•••• 5678"
  }
}

400 A required field is missing.

DELETE/beneficiaries/:idRemove a beneficiary

Example request

DELETE /beneficiaries/B001

Example response · 200 OK

{ "message": "Beneficiary deleted." }

404 Beneficiary ID does not exist.

!

Important security note

This project uses sample data in memory and is only for learning. It does not connect to accounts or move real money. A production banking system needs secure authentication and authorization, encrypted transport and storage, durable database transactions, audit logging, fraud monitoring, rate limits, and additional security controls. The in-memory transfer update is synchronous for this single-process demo; it is not a substitute for a database transaction.
